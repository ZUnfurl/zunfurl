# Example Brand 商品目录与内容运营手册

本文面向使用 **C 零售目录与内容运营基础框架（C Retail Catalog & Content Foundation）** 的日常内容编辑和商品管理员。你只需要使用 Shopify 和 Sanity Studio，不需要接触代码、命令行、GitHub 或 Cloudflare。

本手册只覆盖目录和内容运营，不覆盖 Cart、Checkout、支付、订单、税务、配送、履约、实时价格或实时库存。

## 基本原则

- Shopify 提供只读目录事实：商品是否存在、商品名、handle、商品媒体和受支持的目录结构摘要。
- Sanity 管页面内容：商品详情页文案、故事内容、SEO、各语言是否上线，以及商品内容归档和取消归档。
- Cloudflare 和 GitHub Actions 负责自动构建和上线网页，正常情况下不需要手动操作。
- 不要在 Sanity 或静态内容里维护价格、库存、SKU、订单、支付或履约状态。
- Shopify 映射是只读的；Sanity 不反向编辑 Shopify 商品或交易数据。

## 日常入口

打开 Sanity Studio 后，主要使用两个入口：

- 商品上线向导：用于为一个 Shopify 目录项创建网站商品内容。
- 商品工作台：用于检查内容状态、同步 Shopify 只读目录映射、编辑语言页面、下线语言、归档或取消归档商品内容。

日常运营优先使用这两个入口。普通编辑不要直接删除底层文档。

## 创建一个新的商品目录内容

适用场景：Shopify 里已经创建了可供只读读取的商品记录，现在要给网站创建商品页面和编辑内容。

操作步骤：

1. 先在 Shopify 创建商品记录，并确认商品名、handle、图片和目录基础信息正确。
2. 打开 Sanity Studio。
3. 进入商品上线向导。
4. 从 Shopify 商品列表里选择要上线的商品。
5. 选择要发布的语言。
6. 选择复制的模板商品。
7. 确认创建商品内容。
8. 回到商品工作台，打开对应语言页面检查文案、SEO 和页面内容。
9. 确认无误后发布对应语言页面。
10. 等待自动构建完成后，检查前台网页。

如果只想先上线英文，只选择或发布 English。Français 和简体中文可以保留为草稿，不需要删除。

## 只上线某一种语言

适用场景：商品已经准备好，但暂时只发布英文页面。

操作方式：

1. 在商品工作台找到该商品。
2. 打开 English 页面，确认内容。
3. 将 English 设置为上线并发布。
4. Français 和简体中文保持草稿或就绪状态。

前台只会生成已上线的语言页面。未上线语言不会进入前台构建。

## Shopify 改了商品名、图片或目录结构

Shopify 当前可售/不可售状态只作为运营提示，不决定 Sanity 商品内容能否上线。内容上线资格取决于 Product GID 与 handle 映射完整、商品主档为运营状态，以及对应语言页明确设为上线；价格和库存变化不会自动改写语言上线状态。

适用场景：Shopify 里修改了商品名、handle、主图或受支持的目录结构摘要，Sanity 商品工作台提示映射需同步。

操作方式：

1. 在 Shopify 完成商品修改。
2. 打开 Sanity Studio 的商品工作台。
3. 找到对应商品。
4. 如果看到映射需同步，点击同步 Shopify 映射。
5. 等待提示同步成功。
6. 如果商品名变化会影响页面文案，再进入对应语言页面手动修改标题、SEO 或正文。

同步 Shopify 映射只更新 Sanity 里的 Shopify 只读摘要，不会覆盖语言页面的正文、SEO、slug 或故事内容。

## 修改商品页面文案

适用场景：只修改网站展示文案、故事内容、SEO 或某个语言页面。

操作方式：

1. 打开 Sanity Studio 的商品工作台。
2. 找到商品。
3. 点击对应语言的编辑。
4. 修改内容。
5. 点击发布。
6. 等待自动构建完成后检查前台网页。

如果发布后没有立刻看到变化，先等待自动构建完成。仍然没有变化时，再联系技术维护人员。

## 商品语言页面的三块内容

进入某个语言页面后，优先按前台页面位置编辑，不需要理解底层字段名。

1. 上线与路径：控制当前语言是否上线、商品详情页 URL 和商品列表排序。这是运营控制区，不对应某个前台视觉模块。
2. 商品卡片：对应产品列表页里的商品卡。只维护商品卡片真正显示的主图、商品标题、卡片简述和链接文案。
3. 商品详情头部：对应商品详情页顶部。主要维护系列名、商品标题、一句话卖点、商品描述和媒体 fallback。轮播按钮、区域标签等无障碍文案由系统按语言生成，日常运营不需要编辑。商品主图和受支持的媒体优先来自 Shopify 商品媒体。
4. 商品故事页：对应商品详情页向下滚动后的全屏图文故事。每一个故事章节对应前台一屏，维护故事图片、章节眉标、章节大标题、正文、补充说明和图片说明。

如果某个字段说明里写着“兼容字段”或“当前前台未直接显示”，日常运营可以先不修改。图片来源的默认原则是：商品主图和 SKU 图集归 Shopify；品牌故事、Editorial 和页面内容图归 Sanity。

## 下线某个语言页面

适用场景：商品目录记录仍然保留，但某个语言页面暂时不展示。

操作方式：

1. 打开商品工作台。
2. 找到商品。
3. 在对应语言旁点击下线语言。
4. 确认后，该语言页面不会再进入前台构建。

这不会影响其他语言页面，也不会影响 Shopify 商品本身。

## 重新启用某个语言页面

适用场景：之前下线了某个语言页面，现在准备重新编辑或上线。

操作方式：

1. 在商品工作台找到该商品。
2. 找到已归档或已下线的语言页面。
3. 将该语言页面回到草稿状态。
4. 检查内容。
5. 确认无误后再发布上线。

回到草稿状态不会自动上线，目的是让编辑先检查内容。

## 归档整个商品

适用场景：商品已经停用、废弃，暂时不希望它继续出现在前台和日常运营列表中。

操作方式：

1. 打开商品工作台。
2. 找到商品。
3. 点击归档整个商品。
4. 确认后，该商品不会进入前台构建。

归档不会删除内容，也不会批量修改各语言页面状态。以后取消归档时，原来的语言状态仍会保留。

## 取消归档商品内容

适用场景：之前归档的商品需要重新启用。

操作方式：

1. 在商品工作台切换到已归档视图。
2. 找到商品。
3. 点击取消归档。
4. 检查各语言页面状态。
5. 按需要发布或下线语言页面。

## 删除规则

日常运营不要删除单个语言页面。某个语言暂时不展示时，使用下线语言；以后需要重新启用时，让页面回到草稿状态并重新检查。

整档删除只适合清理确认废弃的整组商品内容，例如错误创建的测试商品。整档删除应该同时处理商品主档和它关联的语言页面，不保留单个语言孤岛。

当前版本以归档和取消归档作为日常内容生命周期。整档删除放在管理员危险区，只能在商品已归档后执行。删除前需要输入商品 handle 明确确认。

归档和取消归档不是 Backup 或 Restore，也不会创建恢复点。整档删除前，Studio 会在同一 Sanity 项目中创建回收站副本，并可在文档 ID 未被占用时尝试还原；但该副本没有独立存储、保留期、校验和或灾难恢复保证。它不属于 Production Backup 或 Disaster Recovery Restore，运营上仍应把整档删除视为可能不可恢复。

整档删除只删除 Sanity 商品内容，不删除 Shopify 商品。是否删除或保留 Shopify 商品，需要在 Shopify 后台单独判断。

如果误删，可能导致页面和语言内容永久丢失。普通商品内容停用使用归档，普通语言停用使用下线语言。

## 什么时候需要联系技术维护人员

以下情况需要联系技术维护人员：

- Shopify 商品已经存在，但商品上线向导找不到。
- 商品工作台显示 Shopify 不可读取。
- 点击同步 Shopify 映射后仍然显示映射需同步。
- 发布成功后，GitHub Actions 或 Cloudflare 部署失败。
- 前台页面大面积丢失或多个商品同时异常。
- 误删了商品内容或语言页面；应立即停止继续编辑，且当前没有恢复保证。
- 需要批量导入、批量删除或处理大量内容异常。

普通文案修改、单个语言上下线、商品归档和取消归档，运营人员可以自行完成。
